# sauce-ui-autotest 质量优化执行指令（执行端专用）

> 本文档是唯一指令来源。执行端（你）负责实现与方案决断；管控端负责验收与红线管控。
> 台账见同目录《优化执行台账.md》——每完成一项任务必须更新，这是断点恢复的唯一依据。

## 0. 角色与总目标

你是本仓库质量优化的**执行工程师**。总目标：在**不降低任何现有测试能力**的前提下，
偿还代码评审发现的技术债务，把本项目从"单点优秀"推进到"全方位优秀"。

你的产出会被人逐项验收。验收不是走形式：每项任务有明确 DoD（完成定义），
不满足 DoD 的提交会被打回。请先读完本文件再动手。

执行环境（Windows）：
- Python 虚拟环境：`.venv/`（命令用 `.venv/Scripts/python`、`.venv/Scripts/ruff`）
- 冒烟自测：`.venv/Scripts/python -m pytest -m smoke --browser=chrome`
- 静态检查：`.venv/Scripts/ruff check .`
- 默认测试目标为线上 saucedemo；若公网抖动导致偶发失败，可用
  `BASE_URL=http://127.0.0.1:8000/` + `python scripts/serve_local_site.py --port 8000`
  切本地托管站点复验（CI 同款确定性环境）。

## 1. 红线（违反任意一条 = 立即停止并上报，不允许自行裁量）

1. **不降低断言强度**：任何现有用例的断言数量、比较方式（==精确匹配/Decimal计算）、
   覆盖场景不得删减或放宽。
2. **不删除有效兜底**：JS 点击兜底、URL 直达兜底、刷新复核、登录被拒重试——这些是
   实战验证过的稳定性资产。只能**收敛实现**（统一入口），不能**取消行为**。
3. **不引入 `time.sleep` 与隐式等待**（录屏线程内的分段休眠除外，那是既有设计）。
4. **不硬编码回归**：账号/密码/期望文案/商品数据一律留在 `config/env.yaml`。
   修复硬编码指把值**移入配置**，不是把别的值写死进代码。
5. **配置向后兼容**：`env.yaml` 现有字段不得改名/删除/改语义，只允许新增。
6. **提交纪律**：每项任务至少一个独立 commit（格式见 §4），保持单任务可回滚。
   禁止把多项任务混进一个大 commit。
7. **不动 testsite/**：静态站点产物是 CI 的确定性基线，一律不碰。

## 3. 任务清单（每项含目标 / 边界 / DoD / 决策点）

### 第一阶段：P0（正确性与结构性，必须最先做）

#### T1 · 统一兜底点击梯子（最大 DRY 债）

现状：BasePage 已有 `click_until`（base_page.py:146），但 6 处页面方法各自手写了
"原生 click → 轮询成功条件 → JS click →（可选刷新复核）→ 重试"的同构循环：
`InventoryPage.add_to_cart / remove_from_cart / click_product_link / open_cart`、
`CartPage.click_checkout / remove_item`、`MenuPage.click_logout`。

- **目标**：BasePage 提供一个统一的健壮点击原语（名字你定），支持成功条件谓词、
  可选钩子（刷新复核 / URL 兜底 / 菜单重开等页面特有逻辑），pages 层 6 处循环改调用。
- **边界**：各方法对外语义保持等价——成功条件、兜底顺序、各级超时预算、
  最终抛出的异常类型与中文消息不变（消息措辞可以微调，语义不可变）。
- **DoD**：
  1. 全项目 grep 不再有手写的"原生→JS→重试"复制循环（允许页面类保留≤5行的个性化钩子）；
  2. `add_to_cart` 独有的"刷新后从 localStorage 恢复状态"兜底以钩子形式保留且仍生效；
  3. `click_logout` 的 Cookie 清除 + URL 兜底行为保留；
  4. ruff 通过 + smoke 通过；
  5. 台账中列出每个页面方法改造前后的语义对照表（一行一个方法）。
- **决策点**：钩子的形态（回调/参数对象/子类覆写）由你定，倾向最简方案。

#### T2 · 修复 ScreenRecorder 迭代并发 bug

现状：失败钩子（conftest.py:336）调用 `save_gif()` 时录制线程**仍在运行**
（stop 在 teardown 才调），`screen_recorder.py:91` 迭代 deque 期间后台线程并发 append，
可能抛 `RuntimeError: deque mutated during iteration`，被 except 吞掉表现为偶发丢录屏。

- **目标**：迭代前先获得稳定快照（锁保护或先置 stop_event 再快照），并保留优雅降级。
- **DoD**：
  1. 快照与后台 append 不可能同时迭代同一容器（代码审查可论证）；
  2. 降级路径（帧数<2 / Pillow 缺失）行为不变，但合成失败必须留 WARNING 以上日志；
  3. 写一段≤30行的并发自证（临时脚本或单测：并发 append + save_gif 循环 N 次无异常），
     结果贴进台账，脚本不入库。
- **决策点**：锁 vs 停止标记，你定。

#### T3 · 配置读取防篡改封装

现状：`YamlUtil.read_yaml` 返回共享可变 dict；conftest.py:50/64 在 import 期**原地改写**
该 dict（WAIT_TIMEOUT/BASE_URL），全项目模块级 `CONFIG = YamlUtil().read_yaml(...)`。
能工作纯靠 conftest 最先加载的顺序，且任何用例可静默污染配置。

- **目标**：配置的"环境覆写"收敛为一个显式入口（如 `get_effective_config()` 或 Config 类），
  `read_yaml` 对外返回深拷贝（配置量小，开销可忽略）。
- **边界**：`WAIT_TIMEOUT / BASE_URL / HEADLESS / RECORDING / EDGE_DRIVER_PATH`
  五个环境变量的现有行为一字不差地保留；各测试模块的 `CONFIG` 用法迁移成本尽量低。
- **DoD**：
  1. 模块级读取拿到的配置已包含环境覆写结果（加载顺序不再敏感）；
  2. 用例层改 `CONFIG` 不会影响其他用例（可用一个临时探针脚本验证后删除）；
  3. smoke 通过；CI 的 BASE_URL 本地站点路径在本地用同款环境变量复验一次。
- **决策点**：Config 类 vs 函数 + deepcopy，你定；数据文件写回（write_yaml）语义保留。

### 第二阶段：P1（效率与可观测性，T1~T3 验收通过后开始）

#### T4 · pytest-xdist 并行执行

- **目标**：本地与 CI 支持并行，全量执行时间显著缩短。
- **DoD**：
  1. `requirements.txt` 增加锁定版本的 pytest-xdist；
  2. 本地 `-n auto` 跑通全量，结果与串行一致（允许重跑后一致）；
  3. Allure 结果多 worker 正确合并，`generate_report.py` 去重逻辑仍有效（报告条目数正确）；
  4. CI：smoke job 启用并行；pages job 全量并行（worker 数你定，写明理由）；
     Xvfb 改为常驻单实例 + `DISPLAY` 共享（多 worker 各自 xvfb-run 会抢 display）；
  5. ScreenRecorder 与并行共存确认（进程隔离天然安全，写明结论即可）。
- **决策点**：worker 数、CI 分阶段启用策略。
- **注意**：T4 之前先确认 T3 已完成（配置覆写与进程模型相关）。

#### T5 · find 系列失败取证统一

find_element_clickable / find_elements` 超时裸抛，失败现场缺失。

- **DoD**：三个方法超时同样产出截图 + page_source 附件 + 中文异常；
  实现**下沉到共享私有方法**，不复制三份；正常路径零额外开销。
  smoke 通过。

#### T6 · 截图目录滚动清理

- **DoD**：`pytest_sessionstart` 中按保留天数（与日志一致取 15 天，可配置进 env.yaml
  新字段）清理 `reports/screenshots/`；清理动作只删 png/gif 且数量记 INFO 日志。

#### T7 · 元素查找日志降级

## 4. 工作流程与提交纪律

1. **开工**：读本文档 + 台账 → 台账把第一个待办任务标"进行中" → 动手。
2. **完成一项**：自测（ruff + smoke，T4 起加并行命令）→ commit → 台账更新该任务行
   （状态/commit hash/关键决策/自测结果/语义偏差说明）→ 下一项。
3. **commit 格式**：`[T1] 统一兜底点击梯子：BasePage 新增 click_robust，6 处页面循环收敛`
   （中文一句话说清改了什么；一个任务多个 commit 用 T编号-1/T编号-2 后缀）。
4. **禁止跨任务大杂烩提交**；重构类任务（T1）若 diff 过大，按页面分批 commit。
5. **每完成一个阶段（P0/P1/P2 全绿）**：在台账写阶段小结（改动统计/风险点/建议验收重点），
   然后通知管控端验收，**验收通过前不进下一阶段**。

## 5. 耐磨（断点恢复）协议

执行可能横跨多个会话/上下文压缩。规则：

- **唯一状态源是台账**。新会话恢复时：读本文档 → 读台账 → 找第一个
  "进行中/待办"任务继续。**不依赖会话记忆。**
- 台账每行必填：`任务ID | 状态(待办/进行中/待验收/完成/搁置/打回) | commit | 决策摘要 | 自测 | 偏差`。
- 被"打回"的任务：先读管控端批注（写在台账该行下方），修复后状态改"待验收"。
- 任何时刻中断，正在改的代码**宁可停在可编译状态**也不要留半成品跨任务。

## 6. 验收口径（管控端将按此逐项检查——请按同标准自检）

1. DoD 全条目满足（逐条核对，缺一条即打回）；
2. `git log` 提交粒度符合 §4；
3. ruff 零违例 + smoke 全绿（必要时全量）；
4. 行为等价抽查：随机抽 2 个被重构的页面方法，对照改造前 git 版本核对兜底顺序与异常语义；
5. 台账记录质量：决策有理由、偏差有说明、上报格式规范；
6. 红线零触碰（含隐性的：如"顺手"简化某条断言、删除某个 fallback 分支）。
